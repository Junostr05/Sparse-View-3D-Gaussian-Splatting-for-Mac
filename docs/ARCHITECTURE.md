# Architecture & Design Decisions

Status: agreed design, nothing implemented yet. Numeric values marked *(initial)* are starting points to be tuned against the golden/eval scenes.

## Goal

A native macOS app that reconstructs a high-quality 3D Gaussian Splatting scene from **3–6 input images**, trains it entirely on the GPU with **hand-written Metal compute kernels**, and lets the user inspect, clean and export it. Results must be free of needle artifacts and floaters, render smoothly, and stay geometrically consistent from unseen viewpoints.

## Decision log

| # | Topic | Decision |
|---|---|---|
| 1 | Scope | Own SwiftUI app with its own Metal pipeline (rasterizer, training, viewport). External tools (InstantSplat, MVSplat, OpenSplat, RadianceKit) are reference only. |
| 2 | Camera poses | v1: import **COLMAP** (`sparse/0/cameras.bin`, `images.bin`, `points3D.bin`) and **ARKit** captures (poses + optional LiDAR depth). Pose-free initialization (MASt3R-style model via Core ML) is a later phase. |
| 3 | Depth loss | **Pearson correlation** between rendered and monocular depth (scale/shift invariant) by default; **additional L1** term when metric LiDAR depth is available. No raw L1 against relative monocular depth. |
| 4 | Initialization | **Dense depth initialization**: per-view monocular depth, scale/shift-aligned to SfM points (or LiDAR), back-projected into a colored point cloud; overlapping regions are deduplicated. |
| 5 | Early stopping | **Leave-one-out, then full retrain**: one run with one view held out picks the best iteration by LPIPS/SSIM; a second run trains on all views up to that iteration. |

| 7 | Verification | **gsplat goldens + Swift CPU reference**: Python script produces golden test cases with gsplat (Apache-2.0); a slow, simple CPU reference in Swift backs fast unit tests; finite-difference checks on every backward kernel. |
| 8 | Project layout | Local **Swift package with separate modules** + app target generated by **XcodeGen** (`project.yml`, no `.xcodeproj` in git). |
| 9 | Hardware | Baseline **M1 with 8 GB**, adaptive Gaussian budget. Features for **M3+** (`MTLGPUFamily.apple9`) are enabled automatically at runtime. |
| 10 | OS | Deployment target **macOS 26**; macOS 27 APIs gated with `#available`. |
| 11 | Delivery order | **Viewer first** (see *Phases*). |
| 12 | App model | **Document-based** (`DocumentGroup`) with a `.gsproj` package; one window per project: sidebar, viewport, inspector. |
| 13 | Distribution | **Open source (Apache-2.0)**, notarized DMG via GitHub Releases. Only commercially usable models in the bundle. |
| 14 | Artifacts | **Measured defaults (revised 2026-11-07, user):** on by default are the depth prior with dense initialisation, the anisotropy loss and opacity + k-NN isolation pruning. **Off by default, switchable in the inspector:** scale cap and pseudo-views (both cost 0.5–3 dB in the measurements), and leave-one-out early stopping (decision 5; twice the training time, no reliable gain). Measurements: `docs/superpowers/plans/2026-11-06-phase-4-addendum-input-pipeline.md`. |
| 15 | SH / opacity | SH degree **1** by default (inspector allows 0–3, warning ≥ 2). Periodic opacity reset **off** (`opacity_reset_interval = 0`). |
| 16 | Export | `.ply` (standard 3DGS layout), `.splat`, `.spz` — all implemented natively in Swift (`.spz` via Apple's Compression framework). |
| 17 | Viewer | Uses the **same tile-based forward rasterizer** as training, so preview and result are identical. |
| 18 | GPU parameter storage | **SoA** `GaussianBuffers` with capacity and count (one buffer per group); Adam m/v use the same layout; initial capacity `min(cap, max(2·n₀, 65 536))`; densification via scan + per-group scatter and blit-back, growth ×1.5 only at densify boundaries (Phase 3 plan D1, D2). |
| 19 | Optimizer | **Adam** (PyTorch form with bias correction, ε 1e-15), gsplat default learning rates, position LR × scene radius with exponential decay, SH DC and rest on separate rates. No optimizer state in checkpoints (D5, D11). |
| 20 | Photometric loss | **L1 + D-SSIM** (λ 0.2, 11×11 σ 1.5 separable window, zero padding), sRGB values without linearization (D6, D7). |
| 21 | Densification | gsplat-style strategy semantics (gradient threshold 2e-4 in NDC-scaled pixels, clone/split at 0.01·R, prune opacity 0.005, prune scale 0.1·R after iteration 3 000); **prune is decided on the parent, before growing**; deterministic budget demotion; the model is never emptied (D8). Deviation from gsplat, which grows first and prunes the grown set. |
| 22 | Initialization | SfM points with 3-nearest-neighbour k-d-tree scales, opacity 0.1; random-cube fallback; no world normalization, a `SceneExtent` scales learning rates and thresholds instead (D9). |
| 23 | Import | COLMAP binaries (SIMPLE_PINHOLE, PINHOLE, SIMPLE_RADIAL, RADIAL, OPENCV with CPU undistortion; other models rejected with a clear error); ARKit JSON schema v1; intrinsics rescaled when the image size differs (same aspect within 1 %); all missing images are reported in one error (D10). |
| 24 | Training concurrency | `TrainingSession` actor around a synchronous `GPUTrainer`; one command buffer per iteration, waiting only at log, densify, preview and final steps; progress as `AsyncStream`; previews are `GaussianCloud` snapshots, never shared GPU buffers (D4, D12). |
| 25 | Memory budget formula | `16·P + 12·K + 340` bytes per Gaussian with `P = 11 + 3K` (756 B at SH 1), cap `0.6 × recommendedMaxWorkingSetSize`, configured maximum 1.5 M (D13). |
| 26 | Inputs (A1) | Video files **and** folders of photos (single iPhone photos, HEIC included) next to the COLMAP and ARKit imports. Per-frame depth comes from the depth model; ground-truth/LiDAR depth stays optional. |
| 27 | Frame selection (A2) | Automatic proposal with manual correction. N frames, user setting, default 6, spread over the camera motion preferring sharp frames (`FrameSelector`); "use all frames" (`FrameSelectionMode.all`) is allowed; video sampling interval default 0.25 s; photo folders default to all photos. The UI warns around ~100 views. |
| 28 | Pose providers (A3) | A `PoseProvider` chain. **Decided 2026-11-06 (Mac session):** the built-in provider is Apple `PhotogrammetrySession` (poses, intrinsics and a point cloud; no signing, download or helper needed). COLMAP is not bundled or downloaded: users who want it run it themselves and use "Import COLMAP…" (posed inputs skip the stage). A foundation-model provider (DUSt3R/MASt3R, optional non-commercial download) stays a later option. Each stage reports success or the reason it failed. Measured on 13 table photos: COLMAP poses score about 0.5 dB (held-out) better than Apple's, see the addendum. |
| 29 | COLMAP delivery (A4) | **Changed 2026-11-06 (user):** the App Sandbox stays, COLMAP is **not** bundled (no XPC helper, no P6). A downloaded or app-written binary cannot be started inside the sandbox (`EPERM`, measured), and dropping the sandbox was rejected. The minimal COLMAP source build from the spike (`Tools/ci/colmap_minimal_build.sh`, licence gate passes) is kept only as a reference. |
| 30 | Depth model (A5) | Depth Anything V2 Small, Apple's Core ML conversion (Float16 `.mlpackage`, Apache-2.0), **downloaded on first use** into the app container, pinned to a Hugging Face commit with a SHA-256 per file; needs `com.apple.security.network.client`. Offline or failed download: depth features stay off with a notice, training still works. Fixed input 518×392. |
| 31 | Quality metric (A6) | SSIM + PSNR on the held-out view; LPIPS is a later option. |
| 32 | Presets (A7) | Fast / Standard / Quality set image size, iterations and the schedules derived from them together (640 px / 3 000, 1 000 px / 10 000, 1 600 px / 15 000 iterations); individual values stay editable. |
| 33 | Frames-only projects (A8) | A video is not copied into the project: only the selected frames (PNG, EXIF stripped) plus provenance (`inputKind`, source file name, timestamp, 35 mm focal length per frame). |
| 34 | Depth alignment | Lives in `SplatDepth` (macOS) next to the Core ML estimator, as the module layout says. Relative inverse depth is fitted in inverse-depth space (`s·p + t ≈ 1/z`), relative depth in depth space; deterministic LMedS over point pairs with MAD gating and two least-squares refits, an occlusion pre-filter, and a one-time kind correction. Views that cannot be aligned keep the depth prior for the (affine-invariant) Pearson term but are skipped by dense init and pseudo-views. Depth problems are reported per view, never thrown. |
| 35 | Rendered depth | Expected depth is an extra composited channel of the existing rasterizer kernels (`Draw = Σ αᵢTᵢzᵢ`, `A = 1 − T_final`), with `∂L/∂z` in accumulator slot 9; the viewer path is unchanged. CPU reference, PyTorch goldens and finite differences back it; an Opus review approved the kernels. |
| 36 | Artifact regularizers | Anisotropy loss (axis ratio ≤ 10) as a gradient kernel, a hard scale cap projection (`0.05·max(R, distance from the extent centre)`), and isolation pruning (k-th neighbour distance far above the median) **on the CPU** at a wait point with in-place compaction (user decision 2026-11-06). Non-finite Gaussians are pruned as destroyed. |
| 37 | Pseudo-views | A fixed pool of interpolated cameras between neighbouring metric views, half resolution, depth-only supervision with forward-warped parent depth, every second iteration from 2 000; their gradient accumulates into the training view's gradients before the single Adam step and does not feed densification statistics. |
| 38 | Early stopping (decision 5 in practice) | `TrainingSession` runs the leave-one-out schedule: run 1 without the held-out view (also excluded from the initial cloud), SSIM-based EMA with patience, run 2 fresh on all views up to `round(best·N/(N−1))`. Below 4 views, or with it switched off, a single run. LPIPS stays a later option (A6). |
| 39 | Trainer hooks | `AuxiliaryLoss` is staged (`pixelGradient`, `parameterGradient`, `postOptimizer`); the GPU trainer follows the CPU trainer's normative step order exactly, and the command buffer of one view is committed before the next view's forward is encoded (shared projection buffers). |
| 40 | Editing (Phase 5, user 2026-11-07) | **Non-destructive**: a project stores only the set of deleted Gaussians (`edits/deleted.bin`, delta + varint, in the base indices of the latest checkpoint) next to the checkpoint; undo/redo works on that set; a new checkpoint (training, import) drops it. The brush selects by projected centre inside a screen-space radius (x-ray, all depths, by default; an optional "Front Only" mode, key F, keeps only the visible surface per screen cell), shown as a 2D overlay; deleting re-uploads the surviving cloud. Editing works in the project window and in the `.ply`/`.splat`/`.spz` viewer window (there it is saved as a new file via export).
| 41 | Export (Phase 5, user 2026-11-07) | One export step with a format choice: `.ply`, `.splat` (DC colour only), `.spz` (gzip; compressed through Apple's Compression framework on macOS, stored blocks on Linux). Exports apply the deletions. `.spz` can also be opened. |
| 42 | Pose-free stage (Phase 6, user 2026-11-07) | **Depth Anything 3** (ByteDance, Apache-2.0 code and Small/Base weights) as a fallback `PoseProvider` after Apple Photogrammetry: one forward pass over all frames gives camera poses, intrinsics, depth and, by unprojection, an initial point cloud. The Core ML package (Base, int8, one function per view count 4/6/8/12/16 and orientation, weights shared) is built by `Tools/da3/convert_da3.py`; it is not bundled and not yet published (owner publishes, e.g. as a GitHub release); until then it can be imported from a local file. Measured on the 13 table photos with 3 held-out views and the Phase 3 training set-up: held-out PSNR 13.4 dB / SSIM 0.23 (Small: 12.9 / 0.23), against 14.2 / 0.34 (Apple) and 14.4 / 0.38 (COLMAP); camera centres 2.0 % and orientation 1.3 degrees from COLMAP (Base). So it is a fallback for captures Apple cannot register, not a replacement. It expects upright images (rotated inputs degrade a lot). |
| 43 | Models not used for Phase 6 | MASt3R and DUSt3R (CC BY-NC-SA, non-commercial), VGGT-1B (non-commercial) and VGGT-1B-Commercial (gated custom licence, 1 B parameters) are not used. |
| 44 | Continued training (v1.1, user 2026-11-07) | After a run, **Continue Training** starts new `TrainingSession` rounds from the stored checkpoint (stored deletions applied). `TrainingConfiguration.continued` derives each round: Adam restarts (decision on checkpoints), SH degree is fixed to the cloud's (`shDegreeInterval = 0`), position LR restarts at 10× its final value, early stopping off, seed varies per round. Optional **Train until stopped** repeats rounds until Stop; every round writes a checkpoint, and `iteration` in the manifest is cumulative. Optional **Add more Gaussians** re-enables densification (threshold ×0.5, first 80 % of a round) with a per-round cap of count × 1.5 up to a user ceiling (1–5 M), still bounded by the device memory budget. Depth is prepared once for all rounds. |
| 45 | Appearance compensation (v1.2) | A learned gain and bias per colour channel and training view is applied to the render before the image loss (`GPUAppearance`, `AppearanceTransform`); the gradient is chained through the gain. An identity pull (weight 0.01) fixes the global gauge. Only the loss sees it: snapshots, checkpoints and exports are unchanged. Held-out views are evaluated with identity. Measured (synthetic benchmark, 4 views, 3 seeds, `SPLAT_BENCHMARK_PERTURB=1`: per-view gain 0.8–1.25 and bias ±0.04): **+3.5 dB** (23.9 vs 20.4); clean scenes −0.1 dB (27.7 vs 27.7). **On by default (user decision 2026-11-08).** On real photos it first exposed a pre-existing NaN in the SSIM backward pass (`ssimMapsV`: `a2 = 2σxy + C2` crosses zero, `s·2μy/a2` and `2s/a2` became 0·∞); the terms are now written without the division by a1/a2 (GPU and CPU reference, regression test `gradientIsFiniteWhereSSIMCovarianceTermCrossesZero`). Until then NaN Gaussians had been created silently in some runs even without appearance. Real-photo measurement of the benefit is still open. Parameters restart at identity in every continuation round. |
| 46 | MCMC densification (v1.2) | After the 3DGS-MCMC paper: relocation of dead Gaussians (opacity < 0.005) onto live ones sampled by opacity, with the opacity/scale correction so the composite opacity is preserved; growth of 5 % per interval up to the budget; SGLD noise gated by `sigmoid(100 ((1 − o) − 0.995))` (only almost transparent Gaussians get noise); L1 regularizers on opacity and scale. Replaces clone/split. Relocation runs on the CPU on the synchronised buffers. Measured: +0.3 dB clean (28.1 vs 27.7) and +0.9 dB perturbed (21.2 vs 20.4), both inside the seed spread (sd 0.8–2.2), at three times the Gaussians (≈160 k vs 55 k). Default off. |
| 47 | Anti-aliasing (v1.2) | Mip-Splatting filters implemented from the paper: 2D filter variance 0.1 with opacity compensation replaces the 0.3 px dilation, and a 3D filter from the per-Gaussian maximum sampling rate over the training cameras (variance 0.2 / ν²) with opacity compensation. Training-time only: `snapshot()` bakes the 3D filter into scales and opacities so the viewer and exporters stay consistent; known limitation: continuing from a baked checkpoint filters twice (small drift, no unbake). Evaluation PSNR uses the same filter. Gradients checked against the CPU reference and finite differences (the gsplat goldens apply to the classic path, which is unchanged). Measured: +0.1 dB clean, +0.4 dB perturbed (inside the seed spread). Default off. |
| 48 | Pose refinement (v1.2) | A learned (ω, τ) per training view, evaluated at 0 and folded into the camera; the gradient includes the mean, Jacobian, covariance and SH view-direction paths (CPU reference + finite differences + Metal-vs-CPU; **no gsplat golden**, a documented gap). Adam steps run at the trainer's sync points on per-view gradient sums. Refined poses are stored in `poses/refined.json`, used by Continue Training and the viewer, dropped by "Retrain from Scratch" and by any re-import. First measurement with learning rates 2e-4 rad / 1e-3 radius was harmful (−1.3 dB clean, −4.3 dB combined with MCMC), so the defaults are now 2e-5 rad and 1e-4 radius: clean −0.5 dB (27.2), perturbed +0.2 dB (20.5), with MCMC 28.4 clean. No measurable gain at 0.5° / 1 % pose errors on 4-view synthetic scenes. Default off. |
| 49 | Model distribution | `docs/models/index.html` lists the optional models; `Tools/da3/prepare_hf_repo.py` prepares the Hugging Face repository (model card, package, checksums) for Depth Anything 3 Base. The DA3 checksums are recorded in `ModelDescriptor.depthAnything3Base`; its `baseURL` stays nil until the owner uploads the package. |
| 50 | Model licences surveyed (2026-11-08) | Usable: **MoGe-2** (MIT code and weights; community Core ML conversions `ebowwa/moge-2-vits-normal-coreml` int8 36 MB and `Kaziko/moge-2-vitl-normal-coreml` 659 MB, MIT, unofficial), **Fixer** (NVIDIA Open Model License, card says commercial use allowed; aimed at autonomous driving; diffusion model, not integrated). Not usable: Difix3D+ original (NVIDIA licence, non-commercial per secondary sources), Depth Pro (Apple `apple-amlr`, research), Depth Anything 3 Large/Giant/Nested (CC BY-NC; Large is contradictory between card and README), VGGT-1B (CC BY-NC), VGGT-1B-Commercial (gated, AUP), Marigold (card Apache-2.0, secondary source RAIL++-M), MVSplat/DepthSplat (code MIT per directory listing, weights licence not found, fixed 2-view 256 px). Primary licence texts were not read for most of them; verify before shipping anything. |
| 51 | Selectable depth estimator (v1.2) | `DepthPriorSettings.estimator`: Depth Anything V2 Small (default) or **MoGe-2 Small int8** (`MoGeDepthEstimator`, `.relativeDepth` maps from the affine-invariant point z channel, fitted by the existing alignment). Measured on the 13 real photos (10 train / 3 held out, COLMAP poses, 5000 iterations, 3 seeds): Depth Anything V2 Small 13.88 dB / SSIM 0.390, MoGe-2 Small 13.45 dB / 0.349, so the default stays Depth Anything. The ViT-L variant was not tested. |
| 52 | Viewer (v1.2) | Cursor-anchored navigation: pan/zoom use the depth under the cursor (`CursorDepth`, 25th percentile of nearby opaque Gaussians), orbit rotates the camera rigidly about the picked 3D point (`ViewCamera.orbit(around:)`, the point stays at its pixel); fly mode (Shift+`) with mouse look and WASD/Q/E. | 53 | Update check (v1.2) | A button next to the version asks `api.github.com/repos/Junostr05/…/releases/latest` (only on click, ephemeral session, no personal data) and compares tag and bundle version (`AppVersion`, pre-releases sort lower). 404 shows "No releases published yet". |
| 54 | Library start screen (v1.4, user 2026-11-08) | The app launches into a **Library** window, never an untitled project (`Window` with `.defaultLaunchBehavior(.presented)`, both `DocumentGroup`s `.suppressed`). ## Module layout (Swift package)

```
project.yml            XcodeGen spec for the app (generates SparseSplat.xcodeproj, not committed)
App/                   SwiftUI app target (@MainActor default isolation)
SplatKit/
  Package.swift
  Sources/
    SplatCore/      Math types, camera models, Gaussian parameter layout, CPU reference rasterizer (forward + backward)   [Linux + macOS]
    SplatIO/        COLMAP binary reader, ARKit capture import, .ply / .splat / .spz read+write, .gsproj bundle I/O       [Linux + macOS]
    SplatMetal/     Metal device/capabilities, buffers, Shaders/*.metal (project, tile binning, radix sort, rasterize fwd/bwd, losses, Adam)   [macOS]
    SplatDepth/     Core ML monocular depth (Depth Anything V2 Small), scale/shift alignment                            [macOS]
    SplatTraining/  Training loop, densify/prune, regularizers, pseudo-views, leave-one-out scheduler, progress AsyncStream
  Tests/
    SplatCoreTests/      CPU reference vs. goldens, finite differences
    SplatIOTests/        Format parsing and round-trips
    SplatMetalTests/     Metal kernels vs. CPU reference and goldens (macOS only)
Tools/golden/          Python script generating golden cases with gsplat (not shipped)
```

- Library modules use default (nonisolated) isolation; only the app target uses `@MainActor` default isolation.
- CPU reference implementations of every training algorithm live in `SplatCore/Training/` and are verified on Linux; `SplatTraining` (macOS-only) wires the Metal kernels into `GPUTrainer` and `TrainingSession`. Image decoding via ImageIO lives in the app; `SplatIO` receives an injected decoder.
- `SplatCore` and `SplatIO` use only the Swift stdlib + Foundation (stdlib `SIMD` types, no `simd` module), so they build and test on Linux — including the cloud container (`Tools/install-swift-linux.sh`).
- Shaders ship as resources (`.copy("Shaders")`) and are compiled at runtime with `MTLCompileOptions.mathMode = .safe`. This makes `swift test` work on macOS without Xcode's `.metal` build step and keeps GPU results comparable to the CPU reference.
- Phase 1 opens `.ply` / `.splat` directly as read-only documents; the `.gsproj` project document arrives with training in Phase 3.

## Phases

Named *Phase* (not "M1…") to avoid confusion with chip names.

1. **Viewer** — document app shell, Metal viewport, import and smooth rendering of `.ply` / `.splat`.
2. **Differentiable rasterizer** — forward/backward kernels, CPU reference, gsplat goldens, finite-difference checks.
3. **Training** — COLMAP/ARKit import, Adam, densification/pruning, training from SfM points. *(Done: verified on CI incl. GPU trainer overfit tests; manual check of the app flow with a real COLMAP dataset pending.)*
4. **Sparse-view quality** — depth prior (Pearson + optional L1), dense depth init, pseudo-views, artifact regularizers, leave-one-out scheduling.
5. **Editing & export** — brush tool for floaters in the viewport, `.ply` / `.splat` / `.spz` export.
6. *(later)* **Pose-free** — MASt3R-style initialization via Core ML for uncalibrated images.

## Training defaults

| Parameter | Default |
|---|---|
| SH degree | 1 |
| Opacity reset interval | 0 (off) |
| Depth loss | Pearson; + L1 when metric depth exists |
| Anisotropy | max axis ratio ≈ 10 *(initial)* |
| Scale cap | fraction of scene extent *(initial)* |
| Opacity pruning | threshold ≈ 0.005 *(initial)* |
| Isolation pruning | k-NN distance outliers |
| Pseudo-views | interpolated poses between training cameras, depth-regularized |
| Early stopping | leave-one-out (held-out view: an interior/interpolating camera, not an extreme one), then full retrain |
| Iterations | 10 000 (SH degree grows by one every 1 000 iterations) |
| Densification | iterations 500–6 000, every 100 |
| Maximum image side | 1 600 px (integer box downsampling, intrinsics scaled) |
| Background | black |
| Maximum Gaussians | 1.5 M, further limited by the memory budget |

## Memory budget (Unified Memory)

Per Gaussian during training: parameters + gradients + Adam m + Adam v = 4 × floats.

- SH 1: 23 floats → ~368 B per Gaussian
- SH 3: 59 floats → ~944 B per Gaussian

The measured budget per Gaussian is higher because of the renderer, statistics and densify scratch buffers (see decision 25: 756 B at SH 1, 1 476 B at SH 3).

Plus tile binning/sort buffers. The budget is derived at runtime from `MTLDevice.recommendedMaxWorkingSetSize` and the SH degree; densification stops at the cap. 8 GB machines target roughly 1–2 M Gaussians; sparse-view scenes usually need a few hundred thousand.

## Hardware capability tiers

| Tier | Detection | Extras |
|---|---|---|
| Base (M1+) | `MTLGPUFamily.apple7` | Full training + viewer; mesh shaders are available here too (Metal 3) |
| M3+ | `MTLGPUFamily.apple9` | Hardware ray tracing (e.g. precise brush picking), Dynamic Caching benefits |

Every feature must have a base-tier fallback.

## Project bundle (`.gsproj`)

A `FileDocument` whose contents are a manifest plus relative-path files (all on `Data`, Linux-testable in `SplatIO`):

```
Scene.gsproj/
  manifest.json      formatVersion 1, source, training configuration, checkpoint record
  images/            copied input images (self-contained)
  poses/colmap/      cameras.bin, images.bin, points3D.bin   (or poses/arkit.json)
  checkpoints/
    latest.ply       standard 3DGS PLY, no optimizer state (resume restarts Adam)
```

The manifest also records `inputKind` (`video`, `photos`, `colmap`, `arkit`) and, for projects built from frames, `frameProvenance`: per image its source file name, the video timestamp and the 35 mm-equivalent focal length. All three are optional, so Phase 3 projects still load.

Newer `formatVersion`s are rejected. `depth/` and `exports/` are added by Phases 4 and 5.

## UI (Liquid Glass)

- Window: `NavigationSplitView` — sidebar (input images), detail (viewport), `.inspector` (training parameters, metrics).
- Viewport, thumbnails and previews are **content layer** — no glass.
- Floating viewport controls (orbit/zoom/reset, render mode, brush) are one `GlassEffectContainer`; training start is the single `.glassProminent` action.
