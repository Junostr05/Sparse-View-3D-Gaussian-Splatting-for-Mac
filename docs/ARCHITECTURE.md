# Architecture & Design Decisions

Status: agreed design, nothing implemented yet. Numeric values marked *(initial)* are starting points to be tuned against the golden/eval scenes.

## Goal

A native macOS app that reconstructs a high-quality 3D Gaussian Splatting scene from **3–6 input images**, trains it entirely on the GPU with **hand-written Metal compute kernels**, and lets the user inspect, clean and export it. Results must be free of needle artifacts and floaters, render smoothly, and stay geometrically consistent from unseen viewpoints.

## Decision log

| # | Topic | Decision |
|---|---|---|
| 1 | Scope | Own SwiftUI app with its own Metal pipeline (rasterizer, training, viewport). External tools (InstantSplat, MVSplat, OpenSplat, RadianceKit) are reference only. |
| 2 | Camera poses | v1: import **COLMAP** (`sparse/0/cameras.bin`, `images.bin`, `points3D.bin`) and **ARKit** captures (poses + optional LiDAR depth). Pose-free initialization (MASt3R-style model via Core ML) is a later phase. |
| 3 | Depth loss | **Pearson correlation** between rendered and monocular depth (scale/shift invariant) by default; **additional L1** term when metric LiDAR depth is available. No raw L1 against relative monocular depth. |
| 4 | Initialization | **Dense depth initialization**: per-view monocular depth, scale/shift-aligned to SfM points (or LiDAR), back-projected into a colored point cloud; overlapping regions are deduplicated. |
| 5 | Early stopping | **Leave-one-out, then full retrain**: one run with one view held out picks the best iteration by LPIPS/SSIM; a second run trains on all views up to that iteration. |
| 6 | Gradients | **Pure Metal**, all forward/backward passes, GPU radix sort, Adam and losses hand-written. No autodiff framework. |
| 7 | Verification | **gsplat goldens + Swift CPU reference**: Python script produces golden test cases with gsplat (Apache-2.0); a slow, simple CPU reference in Swift backs fast unit tests; finite-difference checks on every backward kernel. |
| 8 | Project layout | Local **Swift package with separate modules** + app target generated by **XcodeGen** (`project.yml`, no `.xcodeproj` in git). |
| 9 | Hardware | Baseline **M1 with 8 GB**, adaptive Gaussian budget. Features for **M3+** (`MTLGPUFamily.apple9`) are enabled automatically at runtime. |
| 10 | OS | Deployment target **macOS 26**; macOS 27 APIs gated with `#available`. |
| 11 | Delivery order | **Viewer first** (see *Phases*). |
| 12 | App model | **Document-based** (`DocumentGroup`) with a `.gsproj` package; one window per project: sidebar, viewport, inspector. |
| 13 | Distribution | **Open source (Apache-2.0)**, notarized DMG via GitHub Releases. Only commercially usable models in the bundle. |
| 14 | Artifacts | **Full set on by default**: anisotropy loss, scale cap, opacity + k-NN isolation pruning, pseudo-views with depth regularization. |
| 15 | SH / opacity | SH degree **1** by default (inspector allows 0–3, warning ≥ 2). Periodic opacity reset **off** (`opacity_reset_interval = 0`). |
| 16 | Export | `.ply` (standard 3DGS layout), `.splat`, `.spz` — all implemented natively in Swift (`.spz` via Apple's Compression framework). |
| 17 | Viewer | Uses the **same tile-based forward rasterizer** as training, so preview and result are identical. |

## Module layout (Swift package)

```
project.yml            XcodeGen spec for the app (generates SparseSplat.xcodeproj, not committed)
App/                   SwiftUI app target (@MainActor default isolation)
SplatKit/
  Package.swift
  Sources/
    SplatCore/      Math types, camera models, Gaussian parameter layout, CPU reference rasterizer (forward + backward)   [Linux + macOS]
    SplatIO/        COLMAP binary reader, ARKit capture import, .ply / .splat / .spz read+write, .gsproj bundle I/O       [Linux + macOS]
    SplatMetal/     Metal device/capabilities, buffers, Shaders/*.metal (project, tile binning, radix sort, rasterize fwd/bwd, losses, Adam)   [macOS]
    SplatDepth/     Core ML monocular depth (Depth Anything V2 Small), scale/shift alignment                            [macOS]
    SplatTraining/  Training loop, densify/prune, regularizers, pseudo-views, leave-one-out scheduler, progress AsyncStream
  Tests/
    SplatCoreTests/      CPU reference vs. goldens, finite differences
    SplatIOTests/        Format parsing and round-trips
    SplatMetalTests/     Metal kernels vs. CPU reference and goldens (macOS only)
Tools/golden/          Python script generating golden cases with gsplat (not shipped)
```

- Library modules use default (nonisolated) isolation; only the app target uses `@MainActor` default isolation.
- `SplatCore` and `SplatIO` use only the Swift stdlib + Foundation (stdlib `SIMD` types, no `simd` module), so they build and test on Linux — including the cloud container (`Tools/install-swift-linux.sh`).
- Shaders ship as resources (`.copy("Shaders")`) and are compiled at runtime with `MTLCompileOptions.mathMode = .safe`. This makes `swift test` work on macOS without Xcode's `.metal` build step and keeps GPU results comparable to the CPU reference.
- Phase 1 opens `.ply` / `.splat` directly as read-only documents; the `.gsproj` project document arrives with training in Phase 3.

## Phases

Named *Phase* (not "M1…") to avoid confusion with chip names.

1. **Viewer** — document app shell, Metal viewport, import and smooth rendering of `.ply` / `.splat`.
2. **Differentiable rasterizer** — forward/backward kernels, CPU reference, gsplat goldens, finite-difference checks.
3. **Training** — COLMAP/ARKit import, Adam, densification/pruning, training from SfM points.
4. **Sparse-view quality** — depth prior (Pearson + optional L1), dense depth init, pseudo-views, artifact regularizers, leave-one-out scheduling.
5. **Editing & export** — brush tool for floaters in the viewport, `.ply` / `.splat` / `.spz` export.
6. *(later)* **Pose-free** — MASt3R-style initialization via Core ML for uncalibrated images.

## Training defaults

| Parameter | Default |
|---|---|
| SH degree | 1 |
| Opacity reset interval | 0 (off) |
| Depth loss | Pearson; + L1 when metric depth exists |
| Anisotropy | max axis ratio ≈ 10 *(initial)* |
| Scale cap | fraction of scene extent *(initial)* |
| Opacity pruning | threshold ≈ 0.005 *(initial)* |
| Isolation pruning | k-NN distance outliers |
| Pseudo-views | interpolated poses between training cameras, depth-regularized |
| Early stopping | leave-one-out (held-out view: an interior/interpolating camera, not an extreme one), then full retrain |

## Memory budget (Unified Memory)

Per Gaussian during training: parameters + gradients + Adam m + Adam v = 4 × floats.

- SH 1: 23 floats → ~368 B per Gaussian
- SH 3: 59 floats → ~944 B per Gaussian

Plus tile binning/sort buffers. The budget is derived at runtime from `MTLDevice.recommendedMaxWorkingSetSize` and the SH degree; densification stops at the cap. 8 GB machines target roughly 1–2 M Gaussians; sparse-view scenes usually need a few hundred thousand.

## Hardware capability tiers

| Tier | Detection | Extras |
|---|---|---|
| Base (M1+) | `MTLGPUFamily.apple7` | Full training + viewer; mesh shaders are available here too (Metal 3) |
| M3+ | `MTLGPUFamily.apple9` | Hardware ray tracing (e.g. precise brush picking), Dynamic Caching benefits |

Every feature must have a base-tier fallback.

## UI (Liquid Glass)

- Window: `NavigationSplitView` — sidebar (input images), detail (viewport), `.inspector` (training parameters, metrics).
- Viewport, thumbnails and previews are **content layer** — no glass.
- Floating viewport controls (orbit/zoom/reset, render mode, brush) are one `GlassEffectContainer`; training start is the single `.glassProminent` action.
